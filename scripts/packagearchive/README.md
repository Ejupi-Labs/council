# Council managed execution preview

Version 2.0.0-dev.4. This native preview opens local Git projects and runs native
Codex or Claude Code authoring in isolated managed workspaces. Auto uses a published
economical routing policy, with optional user-reported capacity and declared account
associations. Both connections share one managed worker slot. Exact output,
source-relative candidates, cancellation and recovery evidence remain available.
Live provider compatibility remains separately unqualified for both connections;
the included fixed fake mode uses only local processes and is labelled throughout.

Extract every file, then run `./council --version` and `./council ui`. On Windows,
use `council.exe` or `.\council.exe`. `ui --no-open` reports the private launch URL.
Keep that URL private: it grants access to the local owner. Closing the browser
ends observation only. Explicit CLI execution starts a continuing owner when needed;
`council service stop` closes its admission and settles owned work. Foreground Ctrl+C
requests shutdown. No OS service installer is required.

Council needs no Node.js, npm or Go installation. Git must be installed and on PATH
for projects and source capture. Native execution additionally needs a supported
native executable for the selected connection and its existing vendor login.
Shell wrappers are not launched. Vendor authentication stays vendor-owned; Council
never copies credentials. The UI and SQLite 3.54.1 are embedded. Startup, routing,
capacity and history reads make no model calls. Use the package matching your
operating system and processor. Native runtime qualification is recorded separately
from cross-compilation in repository evidence.

Choose autonomous full access once. That preference maps to native harness permission
controls, with no universal OS sandbox promise. Supervised approval is unavailable.
A task needs no account, quota, price or model form. Unknown task suitability uses a
compatible native default; an explicit suitability hint or a narrowly recognized
document replacement can prefer an economy profile. Original instructions and
literal harness/model pins remain unchanged.

The six fixed profiles use these native selectors:

| Profile | Native selector |
| --- | --- |
| codex-native-default | Native configured default |
| codex-luna-economy | gpt-6-luna |
| codex-sol-general | gpt-6.1-sol |
| claude-native-default | Native configured default |
| claude-haiku-economy | haiku |
| claude-sonnet-general | sonnet |

These dated declarations do not verify account access, actual model identity,
quality or savings. Claude's documented transport minimum is 2.1.259; documented
Haiku/Sonnet alias assumptions are 2.1.293/2.1.284 respectively. Unknown installed
versions remain unverified. A declared account association groups policy and reports;
it cannot select the native authenticated account. Optional reports can exclude busy,
exhausted or denied capacity. Missing observations remain unknown, and unresolved
exhaustion needs an explicit correction.

New tasks default to two managed attempt admissions within one shared 30-minute
wall-clock window from their first admission. Queue, preparation, execution and
settlement share that window; cleanup may continue after a deadline requests Stop.
Explicit grants add authority without launching work. Automatic continuation is OFF
by default. A finite opt-in supports only affirmative pre-launch ineligibility before
any native process preparation/creation; generic native failures, rate-limit prose
and terminal-transient continuation are unsupported triggers. Native internal model
calls, retries and fallback are outside Council's managed admission count.

Usage views separate known sourced counters, missing coverage, fake work, dated
reference prices and native client estimates. Estimates are not billed charges;
unknown charges or allowance never mean zero. Actual-account pins, Council-managed
paid API execution, hard spending caps and exact effective-model guarantees are
unsupported. A native session ID does not imply resume or Council conversation history.

Candidates remain verification pending; independent verification/integration is
reserved for feature 005. This preview does not merge or publish changes. Private
records, workspaces and evidence live under `<user-home>/.council/v2/`, separate from
legacy state. Existing task instructions, history and exact receipts are retained.
A legacy task needs explicit budget adoption before another new attempt; adoption
does not launch it. Current execution requires dev.4/004-v1. Accepted dev.2/dev.3
owners support only the exact maintenance Stop compatibility path, not 004 execution.

Inspect `--help` for reports, task routing, budgets, usage, history, guidance, Stop,
artifact reads and exact request retries. `tasks start --fake --fake-scenario response`
explicitly invokes a local fixture; it never falls back to a vendor or establishes
subscription savings.

The adjacent `.zip.sha256` checks the complete archive. `SHA256SUMS.txt` checks all
distributed files except itself. Keep LICENSE and third-party notices with the
binary. Ejupi Labs artwork remains company identity; generic icons retain MIT notices.
