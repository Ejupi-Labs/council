### Antigravity failure and functional correction

On agy 1.5.1, an initial source review completed. A two-file review then read both permitted fixture files but followed a reference outside its workspace. The native CLI denied that read. Its stdout contained a structured `ERROR` tool event followed by terminal `SUCCESS` with an empty response; stderr reported an approval that headless mode could not prompt for. The old step validator classified `ERROR` as an unsupported state before identifying the failed tool.

The parser now classifies this observed structured `ERROR` as a failed tool operation. It also recognizes the exact known headless-denial diagnostic and emits a body-free explanation. Unknown/malformed states and other diagnostics still fail. Split diagnostic markers fail conservatively without buffering. Neither event ordering permits a later success to restore completion.

Agent prompts now name the actual step directory. Native Antigravity and ACP read guidance keep inspection within that directory and tell agents to report blocked external evidence as unverified. A final NativeRunner two-file review completed in 32.0 seconds with unchanged plan/sandbox flags, zero stderr, exactly two in-workspace reads and a concrete subtraction finding. Private evidence is retained under `.council/native-agy-review-2026-11-05/` using the `probe`, `probe-two` and `scoped-final` prefixes.

### Junie scope diagnosis and remaining ballot defect

Junie 26.7.20 (build 2383.10) advertised its existing `grok-4.5`/high defaults; these were preserved. Three small tasks completed: exact JSON without tools, an in-project source review and an in-project source review with exact JSON. A controlled sibling-file read then reproduced the denial family. The read failed and Junie requested approval under a distinct tool identity with reported kind `other`; Council rejected it. A regression ensures the preceding read cannot relabel this later permission request. This proves a current mechanism, not the unknown historical requested operation.

A full one-member room with source inspection, `autoExecute: false`, and the stronger whole-turn ballot instruction reproduced COU-02. Junie emitted a 78-character inspection notice before the read and a 555-character JSON ballot afterward. Both updates contain only `sessionUpdate` and text content; no message identity, final-answer flag or distinguishing metadata is present. The completion result contains only `stopReason`. Council retained the full response, marked the room `needs_attention` and ran no task. Private evidence is under `.council/junie-live/whole-turn-room.*`.

The whole-turn wording remains a useful instruction, but this probe proves that it is not a reliable repair for this provider behavior. Print mode is not substituted for ACP because equivalent read approval enforcement is not established. The remaining fix requires an authoritative provider final-answer channel or consistently compliant whole-turn output. [The provider reproduction](junie-acp-ballot-reproduction.md) is prepared for that work; no issue or message has been sent externally.
