## Target and account identities

The implementation distinguishes literal requested pins, immutable selected context/profile/
selector and declared account association from native reported identity. Fixed contexts are
Codex and Claude; labels/links do not create logins, quota or parallel workers. Actual account and
native model can remain unknown. Native internal fallback, overage and billing are outside an
enforceable Council financial cap. The normal default requires no reports, prices or account form.

## Budgets and continuation

Defaults are two managed admissions and a 1800-second common wall-clock window anchored at first
admission. Queue and preparation count. Failed/cancelled/blocked work is not refunded. The existing
per-attempt timeout remains an earlier ceiling. Grants/adoption retain prior use and do not launch
work. Legacy schema migration creates no authority; a new attempt requires explicit adoption.

Default automatic continuation is OFF. Only fully proven pre-launch category A is implemented;
a successor has a new immutable decision/attempt and consumes another unit. Unsupported B,
unknown cleanup/evidence, Stop, old owner epochs and persistence uncertainty never authorize a
fallback worker. Task usage subtotals describe returned attempts and separate nonoverlapping
scopes, estimates, reference prices and unknown charges.
