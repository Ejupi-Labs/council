## Qualification classes and reading rules

- **P**: pure policy/validation tests with controlled values; no process/filesystem effect proof.
- **M**: real local database/transport or explicitly labelled metadata fixtures. These establish
  transaction, receipt, schema, paging and control semantics, not the physical effects in a tuple.
- **F**: fixed offline agent/check/publisher processes through real ownership, workspace and
  evidence code. Native transport shapes are fixtures; provider/model/account/usage stay unmeasured.
- **N**: actual native filesystem/process boundary on the executing OS. The ledger currently
  records focused local Windows ARM64 results; that is not six-platform qualification.
- **W**: actual browser/client and owner. Synthetic HTTP transition/active-stage supplements are
  explicitly labelled; they do not supply provider measurements or replace real workflow journeys.
- **X**: extracted native archive runtime with its declared Git prerequisite; Node/npm/Go used
  by qualification tooling do not become application runtime requirements.
- **Compile only** is not an actual OS/runtime pass. **Live provider qualification is UNPERFORMED**
  for this feature; no vendor credential inspection, login/version probe or model call is authorized.

Every matrix row retains **release/7CI OPEN; local visual QA CLOSED**: final serial developer checks/package,
actual rendered/accessibility/brand review, six native jobs and Linux AMD64 race at one frozen
revision, and independent acceptance closure are all required. Focused results referenced below
are limited to the matching source/command recorded in the ledger; the current full rerun is
not credited before its terminal result.

The additional real required-response browser case below supplements T027/VFD-012; it does not
change the frozen requirement text or silently rewrite the task-plan mapping.
