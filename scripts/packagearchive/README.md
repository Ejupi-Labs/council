# Council task graph preview

Version 2.0.0-dev.6. Feature006 implementation is under qualification; its final
local, visual, extracted-package and six-native-target/race gates are not yet
accepted. Features001–005 are accepted; features007–012 remain planned.
This preview opens local Git projects
and runs native Codex or Claude Code in isolated managed workspaces. Auto connects
authoring, proportionate checks, necessary independent review, bounded correction
and captured delivery. Economical routing uses optional user-reported capacity
and declared account associations. Up to two managed workers can run across eligible
native contexts; graph limits and context/shared-account reservations may narrow
capacity. A held migrated legacy claim remains a sole dispatch barrier until settled.
Exact output, source-relative candidates, stage lineage, cancellation and recovery
evidence remain available.
Live provider compatibility remains separately unqualified for both connections;
the included fixed fake mode uses only local processes and is labelled throughout.

Extract every file, then run `./council --version` and `./council ui`. On Windows,
use `council.exe` or `.\council.exe`. `ui --no-open` reports the private launch URL.
Keep that URL private: it grants access to the local owner. Closing the browser
ends observation only. Explicit CLI execution starts a continuing owner when needed;
`council service stop` closes its admission and settles owned work. Foreground Ctrl+C
requests shutdown. No OS service installer is required.

Council needs no Node.js, npm or Go installation. Git must be installed and on PATH
for projects and source capture. Native execution additionally needs a supported
native executable for the selected connection and its existing vendor login.
Shell wrappers are not launched. Vendor authentication stays vendor-owned; Council
never copies credentials. The UI and SQLite 3.54.1 are embedded. Startup, routing,
capacity and history reads make no model calls. Use the package matching your
operating system and processor. Native runtime qualification is recorded separately
from cross-compilation in repository evidence.

Choose autonomous full access once. That preference maps to native harness permission
controls, with no universal OS sandbox promise. Supervised approval is unavailable.
A task needs no account, quota, price or model form. Unknown task suitability uses a
compatible native default; an explicit suitability hint or a narrowly recognized
document replacement can prefer an economy profile. Original instructions and
literal harness/model pins remain unchanged.

These dated declarations do not verify account access, actual model identity,
quality or savings. Claude's documented transport minimum is 2.1.259; documented
Haiku/Sonnet alias assumptions are 2.1.293/2.1.284 respectively. Unknown installed
versions remain unverified. A declared account association groups policy and reports;
it cannot select the native authenticated account. Optional reports can exclude busy,
exhausted or denied capacity. Missing observations remain unknown, and unresolved
exhaustion needs an explicit correction.

Fresh homes retain the005 default of four managed model admissions in one shared 30-minute
wall-clock window from the first admission. Every saved existing default, including
two, is preserved. Task grants, consumed units and deadlines are never refilled by
an upgrade or saved-default change. Author/reviewer/corrector processes consume model
units; local checks/application do not supply model token measurements or consume
model units. Queue, preparation, execution and required settlement share the window;
cleanup may continue after expiry. Explicit grants add authority without launching
work or re-arming old results. Routing continuation is OFF by default; its finite
opt-in supports only proven pre-launch ineligibility before native preparation.
Auto correction separately allows at most one captured cycle for an actual review
blocker or observed required-check failure within remaining authority. Generic
native errors, prose and uncertainty authorize neither retry nor correction.
Native internal calls, retries and fallback are outside the managed admission count.

Usage views separate known sourced counters, missing coverage, fake work, dated
reference prices and native client estimates. Estimates are not billed charges;
unknown charges or allowance never mean zero. Actual-account pins, Council-managed
paid API execution, hard spending caps and exact effective-model guarantees are
unsupported. A native session ID does not imply resume or Council conversation history.

Start needs only a project, task and saved operating preference. A recognized literal
document replacement can use one author and a sufficient observed builtin proof;
other work retains necessary review/check gaps. Agent claims never become check
receipts. Delivery starts as review only; old autonomous permission is not local
delivery consent. Choose prospective verified-local scope once for compatible future
tasks. Ordinary single-link text add/replace/delete under existing parents can then
apply within captured scope while unrelated edits/index remain intact. Unsupported
index, mode, type, symlink or cross-volume changes retain a named gap. Destination
conflicts retain candidate and user work. Immutable candidate creation status is
separate from current workflow qualification and delivery.

Commit, push and publication/deployment require explicit external task scope. The
supported external basis is captured command completion, not remote attestation.
Plain response-only work keeps exact explicit user acceptance and replay; supporting
review does not replace the author's answer. Optional `--workflow author_only`
retains standalone authoring without automatic workflow qualification.

Private records, workspaces and evidence live under `<user-home>/.council/v2/`,
separate from legacy state. Existing instructions/history/receipts retain their
meaning. Explicitly adopt missing budget authority before new work; workflow adoption
separately creates a new version and starts no work. Use Run task for the adopted
first author, then advance eligible existing stages. Current execution requires
dev.6 with execution/workflow/graph contracts006-v1 and current capabilities. Known
dev.2/dev.3/dev.4/dev.5 owners support only their exact maintenance Stop compatibility
path, not current execution.

Optional task groups accept one strict UTF-8 declaration of at most2MiB,16 required
nodes and64 acyclic dependencies in one project. They default to Separate reviewable
results, at most two workers and one finite shared allowance/common window. Nodes,
guidance and derived versions never refill it. Native authors/reviews/corrections/
retries debit the root once; local scheduling, context and materialization add no
model admission or fabricated zero-token measurement.

File dependencies reconstruct accepted predecessor files/index in the actual isolated
receiver; context-only dependencies imply no files. Fan-in retains compatible shared
ancestry once and blocks incompatible changes. Focused context keeps complete original
constraints and attributable evidence behind labelled digests. Missing/inaccessible or
oversize required material blocks;64 supplied references and256KiB combined prompt
limits are transport bounds, not measured provider context capacity.

Only a declared final node can deliver under prospectively captured scope. Every
required node must qualify, and file inputs must reach the final through file edges.
Fresh cumulative checks/review qualify the graph-root-to-final change before a single
application. Intermediate results remain reviewable. Accepted summaries do not qualify
unapplied file deltas; pure-response groups never fabricate file delivery.

```text
council graphs start --project PROJECT_ID --graph-file graph.json --request-id START_REQUEST_ID --json
council graphs get GRAPH_ID --json
council graphs input GRAPH_ID --input INPUT_ID --json
council graphs advance GRAPH_ID --rebind-node NODE_KEY --request-id REBIND_REQUEST_ID --json
council graphs stop-node GRAPH_ID --node NODE_KEY --request-id STOP_REQUEST_ID --json
```

Use returned identities and one request ID per intended mutation. The CLI captures
omitted proof groups once and retains exact intent for retry; explicit proof flags
must be supplied as a complete group. Guidance creates a new version without work.
Advance admits eligible unfinished work within current authority. A named rebind
creates a derived dependency_rebind version only for changed accepted inputs, retaining
originals/options/history without refill. Omission does not rewrite an existing workflow
or replay completed work. Grants and reads start nothing. Group/node Stop retain actual
cleanup and independent sibling results. Restart preserves history and requires fresh
explicit Advance for eligible unfinished work.

Inspect `--help` for workflow preferences, stages, reviews, checks, findings, deliveries,
routing, budgets, usage, history, guidance, Stop, full artifact reads and exact retries.
`tasks start --fake --fake-scenario response`
explicitly invokes a local fixture; it never falls back to a vendor or establishes
subscription savings.
